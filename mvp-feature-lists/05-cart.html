ماژول سبد خرید

Cart ≠ Order ≠ Payment. سبد محل انتخاب و محاسبه است، مدرک پرداخت نیست، و بعد از ایجاد سفارش دیگر منبع تغییر Order نیست. مالک پایدار سبد در MVP: User واردشده با OTP. سبد مهمان تا تأیید PO پیاده نمی‌شود.

Checkout و ساخت Order در سند سفارش است. اینجا فقط تا «سبد معتبر آماده Checkout». تخفیف کد کوپن، اگر در SRS-07 «در صورت وجود» آمده، بدون تأیید PO تعهد نیست. رزرو دائمی موجودی با افزودن به سبد انجام نمی‌شود مگر Inventory Policy جدا بگوید.

۱. چهار حالت کاربری — Cart

VISITOR

بازدیدکننده

سبد پایدار سروری ندارد. افزودن/Checkout → OTP. سبد محلی/مهمان و Merge بعد از ورود: نیاز تأیید PO. Checkout مهمان خارج از MVP تا PO.

USER

کاربر / خریدار

مالک Cart. ایجاد/بازیابی سبد فعال، CRUD اقلام، محاسبه، Validate، ورود به Checkout. B2B روی همین سبد.

SELLER

فروشنده

سبد خریدار را نمی‌بیند و مدیریت نمی‌کند. به‌عنوان User می‌تواند برای خودش خرید کند — نه از Seller Panel.

ADMIN

مدیر

سبد مشتری را در پنل ادمین مدیریت نمی‌کند. از Admin Panel خرید B2C ندارد.

سؤالVisitorUserSellerAdmin
سبد پایدار؟ تا تأیید PO خیر یک سبد فعال به‌عنوان User خیر
قیمت خط از کجا؟ Backend در لحظه add/update — نه عدد کلاینت
چند فروشنده در یک سبد؟ معماری باید تحمل کند؛ تفکیک سفارش = تصمیم PO در سند Order

۳. فیچرهای غیرفنی

خریدار

روی صفحه سبد

  • لیست اقلام: تصویر، نام، قیمت واحد، تعداد، جمع خط
  • دکمه +/− و حذف
  • خلاصه مبلغ
  • CTA تسویه اگر سبد معتبر باشد
  • پیام موجودی ناکافی / تعداد نامعتبر / تغییر قیمت — بدون جزئیات داخلی

صفحات UI

  • Cart page
  • Empty cart
  • Quantity controls
  • Remove item
  • Price summary
  • Checkout entry → سند سفارش

۴. فیچرهای فنی

Domain · carts

  • Cart و CartItem جدا از Order
  • یک سبد فعال per User (سیاست چندسبد: PO؛ پیش‌فرض یکی)
  • Add: خواندن محصول از use case کاتالوگ — نه کپی entity
  • قیمت authoritative در execute

API

  • Create / Get active
  • Add / Update / Remove item
  • Clear · Validate · Calculate
  • 401 بدون نشست؛ 403 سبد دیگری

خطا

  • Insufficient stock · Invalid qty · MOQ / pack
  • Product unavailable · Seller not sellable
  • Price changed (رفتار نهایی PO — تا آن حدس نزن)
  • Empty cart checkout forbidden

تست DoD

  • Unit: تعداد، موجودی، MOQ، جمع‌ها
  • Integration: persistence سبد
  • E2E: OTP → add → update → remove
  • منفی: دستکاری قیمت کلاینت رد شود؛ IDOR

حداقل داده Cart

۵. جریان‌های اصلی

A. افزودن

جزئیات Published← اگر Visitor: OTP← Get/create active cart← Validate product/stock/price← Persist item + totals

B. ویرایش

تغییر qty یا حذف← قوانین خرید دوباره← Recalculate

C. آماده‌سازی Checkout

Validate cart← اگر نامعتبر: قفل CTA← اگر معتبر: ورود به جریان Order

۸. خارج از اسکوپ MVP این نیمه

  • ساخت Order و Payment — سند سفارش / Payment
  • AI Cart Assistant · Smart recommendation در سبد
  • سبد چندگانه همزمان (مگر PO)
  • Wishlist به‌عنوان سبد
  • Guest checkout بدون حساب
