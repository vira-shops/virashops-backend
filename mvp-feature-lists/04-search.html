ماژول جستجو و کشف محصول

جستجو، دسته، فیلتر، مرتب‌سازی و کارت محصول — عمومی، بدون اجبار به ورود. Catalog منبع حقیقت است؛ Search ایندکس جدا و ناسازگار نمی‌سازد. موتور MVP: Postgres tsvector / trigram تا وقتی ناکافی شود — Elasticsearch تعهد این نسخه نیست.

دو سطح جستجو: این سند جستجوی فروشگاه عمومی است (کشف کالا). جستجو/فیلتر/صفحه‌بندی سروری داخل پنل ادمین و لیست کالای فروشنده الزام SRS-09 / SRS-03 است، ولی موتور Discovery جدا نیست — همان Postgres با فیلتر مالکیت. AI Search، Semantic Search و Recommendation تعهد MVP نیستند؛ معماری نباید آن‌ها را ببندد.

۱. چهار حالت کاربری — Search

VISITOR

بازدیدکننده

جستجو، Browse دسته، فیلتر، مرتب، کارت، جزئیات — بدون Login. Personalized History و Saved Search ندارد.

USER

کاربر / خریدار

همان کشف عمومی. از نتیجه می‌تواند به سبد برود. تاریخچه جستجو و پیشنهاد شخصی در MVP نیست مگر PO بخواهد.

SELLER

فروشنده

جستجوی ویترین مثل همه. در پنل: فیلتر/جستجوی محصولات خودش — نه کاتالوگ رقبا.

ADMIN

مدیر

جستجو / فیلتر / صفحه‌بندی سروری روی Users، Sellers، Products، Orders. این Discovery فروشگاه نیست؛ ابزار عملیاتی است.

۳. فیچرهای غیرفنی

ویترین

آنچه روی صفحه است

  • نوار جستجو در موبایل و دسکتاپ
  • نتایج با تعداد و کارت استاندارد
  • فیلتر: موبایل Bottom Sheet / دسکتاپ سایدبار — مطابق Figma
  • مرتب‌سازی واضح
  • کلیک کارت → جزئیات محصول
  • پیام خالی به‌جای صفحه سفید

صفحات UI

  • Search Input + Results
  • Filter panel / drawer
  • Sort control
  • Category navigation
  • Empty / Loading / Error / No Result
  • Suggestion dropdown اگر در اسکوپ بیاید

Rating روی کارت «در صورت وجود» است — سیستم نظر در MVP فرض نیست. Group Buying Indicator فقط اگر Group Buying در اسکوپ اجرایی باشد.

۴. فیچرهای فنی

موتور MVP

  • PostgreSQL tsvector / trigram
  • Elasticsearch فقط اگر این کافی نبود — تصمیم CTO با شواهد
  • Query روی Catalog Published؛ نه جدول ایندکس ناسازگار
  • اگر ایندکس جدا ساخته شود باید با رویداد کالا sync شود

API مفهومی (نام نهایی CTO)

  • GET /search
  • GET /search/suggestions — اگر SRCH-10
  • GET /categories و محصولات دسته
  • عمومی: بدون توکن؛ فقط Published

عملکرد و امنیت

  • Pagination؛ جلوگیری از query سنگین
  • Cache در صورت نیاز — نه منبع حقیقت
  • Validation طول/کاراکتر query
  • Rate limit؛ بدون Injection از متن جستجو

تست DoD

  • Unit: ranking ساده، فیلتر Published
  • Integration: ایندکس/tsvector با کالا
  • E2E: جستجو → کارت → جزئیات
  • منفی: Unpublished در نتیجه عمومی نیست
  • Empty query / zero result

۵. جریان‌های اصلی

A. جستجوی متنی

عبارت← Validation + rate limit← Query Published← رتبه + فیلتر + صفحه← کارت‌ها یا Empty← رویداد Analytics

B. کشف از دسته

درخت دسته فعال← لیست Published آن شاخه← فیلتر / مرتب همان API

C. به‌روز شدن ایندکس

کالا ایجاد/ویرایش/قیمت/موجودی/نشر← رویداد دامنه Catalog← جستجو همان داده را می‌بیند

۸. خارج از اسکوپ MVP

  • AI Search · Semantic · Conversational · Voice
  • AI Recommendation · Shopping Assistant · Best Match Engine
  • ML Dynamic Ranking · Predictive Search پیشرفته
  • Synonym / Typo / Fuzzy به‌عنوان تعهد — مگر PO حداقل typo را بخواهد
  • جستجوی تصویری · Saved Search · Personalization
  • نمایش Group Order در نتایج مگر Group Buying در اسکوپ اجرایی باشد
